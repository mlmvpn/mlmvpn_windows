# XHTTP Panel — وورکر کلادفلر

پنل تک‌فایل برای ساخت کانفیگ‌های **XHTTP (stream-one)** روی Cloudflare Workers، با مدیریت کاربر، محدودیت مصرف کل/روزانه/تعداد روز، بن کردن، لینک ساب اختصاصی، صفحه‌ی استتار، و رله‌ی آیپی ثابت (proxyIP) + fragment.

## ویژگی‌ها
- کانفیگ XHTTP که از کانال TLS/443 با fragment عبور می‌کند (سخت‌قابل‌شناسایی).
- مدیریت کاربر: UUID خودکار، سقف مصرف کل، **سقف مصرف روزانه**، مدت اعتبار (روز)، بن/فعال.
- نمایش مصرف کل و مصرف امروز با نوار پیشرفت.
- لینک ساب متنی و JSON برای هر کاربر + صفحه‌ی وضعیت.
- آیپی ثابت از طریق proxyIP (پیش‌فرض `proxyip.cmliussss.net`، قابل تغییر در پنل).
- صفحه‌ی استتار «Welcome to nginx» برای مسیرهای غیرمجاز (ضد ابیوز).
- رمز پنل از طریق Secret ورکر.

## مراحل راه‌اندازی

### ۱. ساخت و اتصال دیتابیس D1

**روش A — از داشبورد (بدون نیاز به تغییر کد):**
1. در کلادفلر یک D1 بساز: **Workers & Pages → D1 → Create**.
2. وارد ورکر شو: **Settings → Bindings → Add → D1 database**، دیتابیس را انتخاب کن.
3. در فیلد **Variable name** هر اسمی بزن (`DB` پیشنهاد می‌شود) و ذخیره کن.

> وورکر بایندینگ D1 را **خودکار تشخیص می‌دهد** — با هر نامی که در بخش Bindings بدهی کار می‌کند (نیازی نیست حتماً `DB` باشد).

**روش B — با wrangler:**
```bash
cd cf-xhttp-panel
wrangler d1 create xhttp-panel-db
```
خروجی یک `database_id` می‌دهد؛ آن را در `wrangler.toml` جایگزین `REPLACE_WITH_YOUR_D1_DATABASE_ID` کن.

### ۲. ست‌کردن رمز پنل (Secret)
```bash
wrangler secret put ADMIN_PASSWORD
```
یا از داشبورد کلادفلر: **Workers → پروژه → Settings → Variables and Secrets** متغیر `ADMIN_PASSWORD` را اضافه کن.

### ۳. دیپلوی
```bash
wrangler deploy
```

### ۴. ورود به پنل
آدرس `/admin` را دستی انتهای دامنه‌ی ورکر بزن:
```
https://<your-worker>.workers.dev/admin
```
با رمزی که در `ADMIN_PASSWORD` ست کردی وارد شو، کاربر بساز، و کانفیگ/ساب را کپی کن.

## نکات
- برای آیپی **کاملاً اختصاصی و ثابت**، در تنظیمات پنل یک proxyIP شخصی (سرور خودت) وارد کن؛ proxyIP عمومی مشترک و غیراختصاصی است.
- محدودیت مصرف روزانه هر ۲۴ ساعت به‌صورت خودکار صفر می‌شود.
- جدول‌های دیتابیس به‌صورت خودکار هنگام اولین اجرا ساخته می‌شوند (نیازی به اجرای `schema.sql` نیست).
