# رله‌ی فهرست VPN Gate

این پروژه یک تابع کوچک است که فهرست عمومی سرورهای VPN Gate را می‌گیرد و به برنامه می‌دهد.

## چرا لازم است

`www.vpngate.net` از ایران به هیچ روشی مستقیم در دسترس نیست:

| مسیر | نتیجه‌ی تست |
|---|---|
| DNS معمولی | `10.10.34.36` — صفحه‌ی مسدودی |
| DNS-over-HTTPS + اتصال به آی‌پی واقعی | `HTTP 403` با بدنه‌ی `type=Invalid Keyword` — DPI هدر `Host` را می‌خواند |
| HTTPS به همان آی‌پی‌ها | اتصال برقرار نمی‌شود |
| رله‌های عمومی (allorigins، codetabs) | `520` / `522` — خودشان هم به vpngate نمی‌رسند |

پس فقط یک رله‌ی خودمان جواب می‌دهد.

## چرا حساب قبلی از کار افتاد

`mlm-proxy.vercel.app` الان `HTTP 402 / DEPLOYMENT_DISABLED` می‌دهد. دو دلیلش:

1. **حجم.** فایل CSV حدود **۱٫۳ مگابایت** است. سهمیه‌ی رایگان Vercel روی پلن Hobby ماهی ۱۰۰ گیگابایت است، یعنی حدود **۷۷٬۰۰۰ دانلود در ماه** — و نسخه‌ی قبلی برنامه هر بار که کاربر وارد صفحه می‌شد یک بار کامل می‌گرفت.
2. **رله‌ی باز.** نسخه‌ی قبلی `?url=` می‌گرفت و هر آدرسی را که می‌دادید واکشی می‌کرد. هرکس آن URL را می‌دید می‌توانست ترافیک خودش را از حساب شما رد کند.

## این نسخه چه فرقی دارد

- **مقصد ثابت است.** دیگر `?url=` نمی‌گیرد، پس رله‌ی باز نیست.
- **کش لبه.** `s-maxage=900` یعنی CDN همان بایت‌ها را ۱۵ دقیقه به همه می‌دهد بدون اینکه تابع اجرا شود یا به vpngate وصل شویم. ده هزار کاربر = یک واکشی.
- **فشرده‌سازی.** CSV عمدتاً base64 است و با gzip حدود یک‌سوم می‌شود؛ یعنی همان ۱۰۰ گیگ حدود **۲۳۰٬۰۰۰ دانلود** جا می‌دهد.
- **پاسخ ناقص را رد می‌کند.** اگر بدنه `#HostName` نداشته باشد یا کوتاه باشد، `502` می‌دهد به‌جای اینکه فهرست خالی به برنامه برسد.

در کنار اینها، خود برنامه هم عوض شد: فهرست روی گوشی ذخیره می‌شود و تا **۷ روز** دوباره گرفته نمی‌شود، و تلاش ناموفق تا **۶ ساعت** تکرار نمی‌شود. این به‌تنهایی مصرف را ده‌ها برابر کم می‌کند.

## ساخت هر حساب

برای هر حساب این مراحل را جدا تکرار کنید:

1. یک اکانت GitHub جدا بسازید (Vercel با GitHub وارد می‌شود و هر حساب Vercel به یک GitHub وصل است).
2. این پوشه (`vercel-proxy`) را در یک ریپوی خصوصی روی همان GitHub بگذارید.
3. در [vercel.com](https://vercel.com) با همان GitHub وارد شوید → **Add New → Project** → همان ریپو را import کنید.
4. تنظیمات را دست نزنید؛ `vercel.json` کارش را می‌کند. **Deploy** بزنید.
5. آدرسی که می‌دهد (`https://<name>.vercel.app`) را یادداشت کنید.

بعد از هر دیپلوی، این را تست کنید — باید CSV برگردد نه خطا:

```bash
curl -s -o /dev/null -w "%{http_code} %{size_download} bytes\n" https://<name>.vercel.app/
```

کد باید `200` و حجم بالای یک مگابایت باشد.

## اتصال به برنامه

آدرس‌ها را در [VpnGateRepository.kt](../android/app/src/main/java/com/mlmvpn/scanner/engines/vpngate/VpnGateRepository.kt) داخل `RELAY_HOSTS` بگذارید. آدرسی که به `=` ختم نشود، مقصدش ثابت است و برنامه چیزی به آن اضافه نمی‌کند:

```kotlin
private val RELAY_HOSTS = listOf(
    "https://mlm-relay-1.vercel.app/",
    "https://mlm-relay-2.vercel.app/",
    "https://mlm-relay-3.vercel.app/",
)
```

برنامه هر نصب را از یکی از این‌ها شروع می‌کند (بر اساس یک عدد تصادفی که یک بار ذخیره می‌شود) و اگر جواب نداد سراغ بقیه می‌رود. اگر ترتیب ثابت بود، همه‌ی گوشی‌ها اول رله‌ی اول را تمام می‌کردند و بعد می‌رفتند سراغ دومی — یعنی حساب‌ها یکی‌یکی مصرف می‌شدند نه با هم.

## نگهداری

- ماهی یک بار در داشبورد Vercel بخش **Usage** را نگاه کنید.
- اگر یکی از رله‌ها به سقف نزدیک شد، یک حساب دیگر اضافه کنید و آدرسش را به فهرست بالا اضافه کنید.
- اگر روزی همه‌شان خطا دادند، برنامه دیگر بی‌صدا رد نمی‌شود: در صفحه‌ی گیت‌وی می‌نویسد به‌روزرسانی نشد و همان فهرست ذخیره‌شده را نشان می‌دهد.
